# M4 Fjall bounded recovery

Status: bounded whole-store preparation and commit are integrated. The initial frozen supplier gates passed but review found three important recovery issues. Their scoped fixes and focused receipts are below; re-review and a fresh joint supplier gate remain. This is not a power-loss qualification.

`Config::open_with_recovery_limits` acquires the common owner lease, admits every journal and standard-tree partition under one ledger, constructs retained replay memtables and tree state, and records cleanup and tail repairs. Only after admission does commit apply retained filesystem actions and start background workers. A blob-separated partition is refused. The existing v2 format is unchanged. The earlier unbounded open remains available, but participates in the same advisory owner lock.

The ledger bounds individual key and value lengths, cumulative physical journal replay bytes, recovery item visits, metadata, physical input and requested allocation capacities. Recovery visits include journal markers and items plus metadata work and are not a count of retained records. Metadata capacity is charged to both its own cap and the allocation cap. Zero padding, unknown and already-persisted entries are physically accounted. Checks precede input-driven payload and metadata allocations. Fixed runtime and configured cache/descriptor infrastructure are outside this named counter; their independently configured limits still apply. Physical allocator or OS OOM remains a platform failure. There is no total-process-memory or universally fallible allocation claim.

The cooperative `.fjall-owner.lock` lives through partition handles, snapshots, iterators and transactional read iterators. It coordinates updated Fjall owners and the host owner lease; older binaries and arbitrary writers are outside that boundary. On a refused first open the newly created lock artifact may be excluded from an inventory comparison, but all preexisting files, including a preexisting lock, must be compared. The fork makes the raw partition tree crate-private and replaces `TrackedSnapshot` dereferencing with lease-carrying forwarding methods; provenance records the API cut. Platform lock behavior beyond the tested host is unqualified.

Successful temporary owners now clean store contents only after the final lease-carrying capability drops. They retain the root directory and the original `.fjall-owner.lock` inode, so a cooperating opener cannot acquire a replacement lock during cleanup. This intentionally changes upstream temporary cleanup: the coordination directory remains. External deletion or replacement of the directory, including by an older binary, is outside the advisory contract. The cleanup lease stays disarmed until opening has fully succeeded, so an I/O error during bounded commit does not trigger recursive deletion of the existing store.

Directory admission precharges input-driven name and path copies before each enumeration step. The Rust 1.99 source audit uses the u16 dirent bound on Linux and Darwin and Windows' 260 UTF-16 name-unit bound with conservative conversion and path-growth allowances; unsupported targets refuse. Known commit path conversions are charged in advance, and orphan deletion uses admitted individual paths rather than an unbounded recursive traversal. The LSM preparation hook currently refuses Windows long or nonabsolute paths pending its normalization audit. These source-derived bounds require independent target/toolchain review. Optional bytes-backed replay is refused pending its allocation audit.

Journal checksums are streamed over the original encoding. Known malformed markers, value types, UTF-8, trailers and checksums return corruption without mutation. Supported physical EOF tails and verified zero padding become deferred repairs. Arbitrary corruption that mimics a valid EOF cannot always be distinguished from a torn write; no open-ended salvage or physical power-loss guarantee is claimed.
