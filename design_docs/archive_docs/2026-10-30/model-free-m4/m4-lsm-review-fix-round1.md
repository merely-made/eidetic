# M4 LSM and Muniment review fixes, round 1

The six Important findings in `m4-lsm-review.md` have corresponding changes and tests. This is the implementer's report, not an independent verdict.

1. Resident reads iterate borrowed skiplist entries. They charge visits and key/value decoded work to both ledgers before comparing bytes or cloning slices, including shadowed and nonmatching entries. `m4-store-review-resident-red-1` failed first; `m4-store-review-resident-green-1` passed zero/exact, shadowed, nonmatching and repeated-failure accounting.
2. Single deletes and all batch deletes now preflight the same owner key and partition-plus-key recovery ceilings as puts. `m4-store-review-delete-red-1` failed before the change and `m4-store-review-delete-green-1` passed refusal, whole-batch preservation and bounded reopen.
3. Empty prefix uses an actually unbounded upper end through the LSM and Fjall interfaces. `m4-store-review-empty-prefix-red-1` failed first; `m4-store-review-empty-prefix-green-2` passed binary `0xff`-leading key presence and corruption reporting in memory and after flush. The first green attempt used `force_flush` with an active flusher and failed due to fixture queue contention; the passing fixture uses `rotate_memtable_and_wait`.
4. Recovery checks an index header and declared payload against its allowed extent before reading the payload or requesting its allocation, then validates every retained data pointer including the first and last. `m4-store-review-index-extent-green-1`, `m4-store-review-index-header-green-1`, and `m4-store-review-pointers-green-2` passed; malformed pointer fixtures verify unchanged segment bytes. The first pointer green attempt had a test encoding-length mismatch; the corrected fixture preserves encoded length.
5. Miniz output is inflated in bounded steps. Before each step the maximum possible output is restricted to the remaining decode allowance on both exclusive mutable ledgers; actual produced bytes are debited immediately after the step and before the next step. Each requested output-buffer capacity is separately charged before allocation, including reallocations. `m4-store-review-miniz-red-2` failed both prior paths; `m4-store-review-miniz-boundaries-1` passed data/index exact cumulative and one-short failure cases, and `m4-store-review-miniz-steps-1` passed multi-step output.
6. Declared index visits are charged to both ledgers before validation traverses entries. `m4-store-review-index-visits-red-1` failed before the change, and `m4-store-review-index-visits-green-1` plus `m4-store-review-index-header-green-1` passed zero-visit refusal, malformed late entries, and repeated failed-work charging in the shared read ledger.

The prefix presence path still scans and merges the full matching range; it may refuse on later work despite an earlier live match. This behavior is now covered by `prefix_presence_refuses_if_later_range_work_exceeds_the_budget` and does not return false on exhaustion. The unused Bloom prototype and test-only data-block wrapper are gated to tests; upstream unsafe/deprecation and preexisting test mut warnings remain baseline.

Combined locked/offline guarded gates on this fix-wave closure: `m4-store-review-wave-lsm-1` passed 64 bounded LSM tests with LZ4 and Miniz, and `m4-store-review-wave-muniment-1` passed 117 native Muniment tests with Fjall and default JSON. The earlier bytes-backed refusal tests passed before this fix wave and must be rechecked on the final closure. Limits remain requested input-induced capacity and work, not allocator overhead, OOM handling or total RSS. Independent whole-layer review and exact final source hashing remain pending.
