# M4 bounded storage: Turnstone integration brief

Status: read-only preparation against Turnstone `e35270230a15a7f27f75f0d50bef1d3eb6f95903`. The supplier API in the storage design is provisional. No host source has been changed or built for this extension. The previous 53-test receipt does not qualify these future changes.

## Owners and boundaries

A complete model-free operation reads three separate Fjall owners, not just the structured sealed owner:

1. `sessions/<id>/memory`: `trail_memory/worker.rs` calls `open_memory` at startup and `Reopen`; `open_memory.rs` calls `FjallStore::open`, bootstraps browsing schema, loads browsing memory, and refreshes the local capture library. Legacy admitted captures use `trail_memory/saved_sources.rs::load_content`, which reads the Fleece annotation and acquisition evidence from this store. The capture library also lists and loads these annotations through `place/captured_collection.rs::refresh_local_capture_library`. Page text, browsing history and legacy capture receipts share it. This owner must be opened bounded to close the model-free capture path. Limits must not silently turn browsing or capture failures into complete research results.
2. `sealed_memory_dir(current_dir)`: `worker.rs` opens on `SetCustody` and `Reopen` using `.ok()`. It serves sealed capture deposit/read/recovery (`sealed_capture.rs`), structured records and results (`sealed_records.rs`), and both property and result pending/completed receipt namespaces (`sealed_record_receipts.rs`, `sealed_result_receipts.rs`). The actor closes and reopens at custody and session lifecycle changes. A bounded open error must remain available to future commands and recovery UI, including exact limit kind, rather than become `None` and generic locked/unavailable text.
3. `<mere root>/retained-clips`: `research_search.rs::snapshot` calls `research::Bridge::clip_view`, which calls `retained_clip::read_sealed`; it opens this separate store with unbounded `FjallStore::open`. Notes are retained clips too. `read_store`, `require_existing_seals`, and Mere's retained-clip reader fetch manifests, records and parts. It currently opens per clip. Model-free search, compare, structured input and evidence open must use bounded opening and reading here as well. Audit other `retained_clip::open` callers for the invariant that a write cannot create an entry above recovery limits; import/export must not create an unbounded bypass to the same live owner. Existing clip payload limits are not storage block or recovery bounds.

The narrow design text calling only for bounded sealed-owner open is incomplete for these actual source paths. Underlying supplier owner ceilings apply to all normal calls on each bounded owner, but that alone creates a fresh budget per Backend call and does not satisfy an operation-wide ledger.

## Propagating limits and failures

- Add host-owned, serializable storage configuration with visible defaults for independent recovery/open limits, per-owner-call read ceilings and shared operation read limits. Represent every supplier dimension without conflating source payload bytes with encoded input, decoded blocks, metadata, requested allocations, visited items, keys and output. Keep zero a real limit; checked conversions for `usize` and `u64`. Never silently derive a block ceiling from `RecordSettings.max_input_bytes`. Show units and current values in settings and distinguish open recovery, storage I/O/decode and source/query limits in errors.
- `research_search_state::{Preferences, StoredPreferences}` already uses a deny-unknown-fields v1 JSON sidecar, with `#[serde(default)]` for later sections and explicit `Default`. Add a separately defaulted storage section, expose fields in the existing structured settings UI and `research_search_values::apply_value`; preserve existing files and unrelated settings, round-trip overrides, fail visibly for malformed/newer files. Search settings currently load lazily in `start_research_search`, after `shell_new` has spawned the trail actor, so this is not sufficient for bounded startup. Load the storage configuration before actor spawn and before any retained-clip read; on invalid configuration refuse storage opens visibly, not fallback silently. Provide a route to edit limits even while opening fails. Apply changed recovery/owner ceilings through an explicit ordered release/reopen or restart boundary, explain when they take effect, invalidate running and accepted research using the existing session/custody/revision machinery, and never overwrite a failed-open store. Do not introduce a new identity or storage format.
- Thread the same configured limits into `TrailCommand::Reopen`, custody adoption and clip owner construction, with immutable per-opening configuration and a generation check; failed/superseded replies cannot reopen stale state. Reopening the same directory must drop its old handles first as it already does. Retain typed limit/error category until the UI boundary, including open I/O versus corruption versus unsupported format versus limit; expose the limit and a safe change/retry route. Existing `Option<FjallStore>` loses this distinction and needs an explicit owner state/result, not `.ok()`. Existing capture-library refresh converts per-record errors into invalid entries; a storage limit must fail the operation and leave the library unavailable, not publish a partial successful refresh. Existing `emit_sealed_capture_recovery` converts verification errors to a generic refusal; preserve actionable limit causes.
- `saved_sources::load_with_sealed` converts every read error into `Entry.error`; `research_search::snapshot` converts errors to exclusions. Capture/clip storage exhaustion must be a whole-operation typed refusal, not missing data or normal incomplete coverage. Ordinary missing/unavailable sources may retain their existing explicit coverage behavior. `stored_page_texts` falls back to empty on any error; audit whether such a fallback can reach a qualified model-free path and surface storage limits wherever completeness is claimed. Error classification must survive `eidetic`/Fleece/Mere wrappers; string inspection is not a sound substitute for typed errors. If supplier wrappers erase `StoreError` kind, request an upstream typed propagation interface before claiming this boundary closed.

## Whole-operation ledger

At entry to each structured Query, Deposit, Inspect, Replay and recovery operation, create one shared read budget from the operation limits and pass the same `Arc`-owned, `Send + Sync` ledger through all work. `research_records_worker::command` currently sends a separate `record_actor::Command` for pending check, each record, result and mutation; `sources` separately invokes `research_search::snapshot`, which sends `TrailCommand::ResearchSnapshot` and opens each clip through `Bridge`. Constructing a fresh ledger in `record_actor::execute` for every command would reset counters and fail the contract. The same ledger must reach session-memory and sealed source calls, clip owner reads, legacy-existence checks, pending property and result inventory, individual receipts, definitions, records and result replay. It must survive unsuccessful calls without refund. Share exact ledger identity across actor handoffs, do not serialize a copied remaining counter or hold a lock across an unrelated wait. Set owner-call ceilings independently at each store open; the supplier must check/debit both ledgers atomically before access, including when the operation ledger is shared across threads and stores.

Replace `structured_bounded_store.rs` post-fetch `get/list/scan` with `get_bounded/list_bounded/scan_bounded`; implement a safe synchronous lock around each bounded call if required by `Backend: Send + Sync`, with no async await while holding it. Specialize legacy-prefix existence to `exists_bounded`, since a complete list capped to one item incorrectly rejects a second match. Complete pending inventories must debit shared item/key/decode/work across both kinds and receipt values. Existing `max_bytes` cleartext, validation and aggregate decoded-snapshot checks remain separate and still apply after storage reads; avoid treating ciphertext, compressed blocks and cleartext as equivalent units. Structured saved-result replay must apply current admission, custody and limit checks just as before. Retain sync fences and exact nonce/idempotency ordering.

For general research search, compare and explicit evidence opens, create a distinct budget per user operation and share it through the same source calls. Ordinary capture operations and startup recovery also need clear, bounded operation scopes or documented owner-call bounds; avoid claiming that per-call defaults establish a shared multi-read operation limit. The clip path opens a store repeatedly, so account recovery/open per open and consider holding one appropriately scoped bounded handle during a single operation; do not claim a single-query recovery cap without implementing it. Open/recovery limits are distinct from read budget and apply before query construction.

Bounded storage does not promise a process RSS cap, bound existing cache/memtable residency, or qualify physical power loss, graphical runtime or full offline fresh-process operation.

## Confirmed cross-layer error erasure

This is an observed dependency, not just a hypothetical risk: Eidetic's `crates/eidetic-core/src/lib.rs` defines `Error { message: String }` and converts `muniment::StoreError` via `err.to_string()`. `typed.rs::load_typed_sealed` uses this error path, so a typed Muniment limit does not by itself reach host callers through Eidetic. Fleece/Mere host adapters also currently return strings. Either preserve typed causes upstream or use a carefully tested operation-local host Backend adapter that records the first typed supplier failure in shared state before returning the trait error, then checks and propagates that state immediately after every wrapped higher-level call, including calls that otherwise return an exclusion or success. Never infer a limit kind by parsing strings. A side channel must be scoped to the exact operation, cover all three stores and nested calls, remain safe for concurrent independent jobs, and cause the whole operation to refuse before publishing partial output. Explicit tests must include upstream conversion and swallowing of a limit error. Ordinary owner calls bypassing that wrapper need their own explicit failure classification; their success cannot establish the shared-ledger contract.
