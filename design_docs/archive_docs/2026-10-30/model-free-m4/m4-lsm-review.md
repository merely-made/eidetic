# M4 LSM and Muniment review

Verdict: **Needs fixes**. The frozen LSM and facade changes do not yet meet the named work-accounting, recovery admission, or complete-inventory contract. The issues below are source findings; no new build or runtime gate was run.

## Important

1. **Memtable entries bypass decoded-work accounting.** `support/patches/lsm-tree/src/bounded_read.rs:154` visits and compares every active and sealed memtable entry, but charges only `VisitedItems`; neither key nor value bytes are charged to `DecodeBytes`, including matching, shadowed, tombstoned, and nonmatching entries. `Memtable::iter` clones its stored slices before the loop (`support/patches/lsm-tree/src/memtable/mod.rs:42`), and the scan can return a key with zero decoded-byte work charged. A large resident table can therefore exceed the configured work ledger, including across repeated operations, without refusal. Charge entry work against both ledgers before accessing/copying it, including discarded entries; exercise zero/exact limits, shadowed entries, and unsuccessful calls.

2. **Deletes bypass recovery key admission.** `crates/muniment/src/fjall_backend.rs:146` calls `remove` without admission, and the batch preflight at line 178 examines only puts. Fjall writes the partition and key into a tombstone journal entry (`support/patches/fjall/src/partition/mod.rs:1093`). Deleting a key longer than the recovery key ceiling can succeed and leave the next bounded open unable to replay that individual entry; a later oversized delete in a batch also bypasses all-batch admission. Apply recovery key admission to single and batch deletes before any batch mutation, and test refused deletion plus reopen.

3. **Empty-prefix inventory can silently omit opaque keys.** `crates/muniment/src/fjall_bounded.rs:100` sets the empty prefix's exclusive upper bound to `[0xff]`; every key beginning with `0xff` lies outside it. Such keys are valid opaque stored bytes even though Muniment's output is UTF-8. An empty list can consequently succeed where a complete inventory should either encounter the invalid UTF-8 key and return corruption or otherwise refuse, and existence can incorrectly return false. Represent an unbounded upper end and cover binary boundary keys in cold and resident storage.

4. **Preparation admits invalid data-block pointers and reads index extents too late.** `support/patches/lsm-tree/src/bounded_segment.rs:49` checks only that the index begins before metadata; the loop at lines 59-62 checks the end after `read_index_block` has read, allocated, and decoded against the file end (`bounded_index_block.rs:39-47`). A declared index payload can cross into metadata/trailer before corruption is recognized, or even produce a limit refusal first. The subsequent check at `bounded_segment.rs:86` checks only increasing handle offsets, not whether each is in the data extent. Thus a checksum-valid index with an offset at or beyond the index area is retained and can pass admission; the bounded read detects it only when the handle is visited (`bounded_read.rs:219-223`), after recovery may have committed earlier mutations. Validate the declared index extent before payload allocation/read and all retained data pointers against their permitted extents during preparation. Include malformed extent and single/last-handle pointer fixtures and unchanged-file checks.

5. **Miniz charges the configured maximum as decoded work, not actual output.** `support/patches/lsm-tree/src/bounded_block.rs:188-198` and `bounded_read_index.rs:205-206` reserve and debit the entire `max_block_decoded_bytes` before inflating, even for a tiny block. Full requested scratch capacity must be charged to allocation, but the contract defines decoded work in actual bytes. For example, a 1 MiB block ceiling with a 1 KiB remaining decode budget refuses even if the stream expands to only tens of bytes; repeated small blocks consume the maximum each time. Use bounded incremental output and debit produced work before each bounded step, retaining the separate full requested-capacity charges. Verify small outputs under large block caps and exact cumulative decode boundaries for both data and indexes.

6. **Index-entry visits are charged after the first traversal.** `support/patches/lsm-tree/src/bounded_index.rs:38-50` walks and validates every encoded handle before charging the count to `VisitedItems`. A zero visit budget therefore still permits a full traversal; an early key limit, malformed entry, or ordering error returns without charging any of those visits. Because the same parser is used for bounded reads through `bounded_read_index.rs`, a shared operation can repeat that failed work without exhausting its visit ledger. Precharge the admitted count before traversal, or debit each actual visit before examining it, retaining charges on failure. Test zero limits and repeated late failures.

## Strengths and bounded observations

- Read ledgers use checked two-ledger admission, and owner ceilings are intersected with call ceilings. The facade routes ordinary bounded-owner `get`, `list`, and `scan` through that path; successful enumeration is collected before return, so a refusal does not return a partial vector.
- The bounded path rereads disk index/data blocks instead of trusting unaccounted cache entries; payload checksums and key/value lengths are checked before separate entry allocation. Explicit bytes/blob refusal and distinct error variants are present. Direct path edges from Muniment to Fjall and Fjall to LSM are present, and the patch README records versions, checksums, licenses, and maintenance limits.
- A snapshot nonce spans each partition bounded call. Source and reported focused tests cover descriptor registrations surviving a tree clone and an iterator outliving its tree; these are narrower than a whole-owner lifetime proof.
- `exists` collects and sorts the whole range before deciding (`bounded_read.rs:408`), so it can refuse on later work even when an earlier live key exists. The contract permits, rather than requires, returning at the first live match. This is a performance and availability limitation, not by itself a specification defect. Add a regression documenting the chosen behavior if retained.

## Clarification: LSM preparation, replay, and commit boundary

This narrows the first Cannot verify item above. The original reviewed snapshot's `bounded_tree.rs:230-238` shows that `PreparedTree::commit` itself performs only deferred `create_dir`, directory fsync, orphan `remove_file`, and return of the retained tree. It accepts no budget and performs no configured limit checks or reads of stored manifest, index, block, or replay input. `prepare` precharges path-conversion capacity for both missing-directory operations and each orphan at lines 98-110 and 398, before commit. The unchanged `file.rs:40-43` opens and syncs the created directory; debug builds also query its metadata. That is filesystem metadata for the deferred operation, not a new read of limit-bearing stored contents. The path-capacity conclusion remains conditional on the documented standard-library/platform estimates; commit may still fail with I/O or physical allocation failure.

`install_replay` is a method on the still-unconsumed `PreparedTree`, so the same value cannot invoke it after its consuming `commit`. At lines 176-210 it performs its configured charges, vector reservations, and checked ID arithmetic before changing that tree's active or sealed memtables; lines 211-223 create the precharged Arc/vector state and then install it. It reads no stored file in this method. This establishes its local ordering relative to that tree's `commit`, not ordering against a different prepared tree: the API does not itself prevent a caller from committing one tree before installing replay in another, and `tree()` exposes the admitted in-memory tree. Whole-Fjall sequencing, retained-input admission before calling this method, and later host operations remain outside this LSM-local conclusion. The local proof does not resolve the invalid pointer/extent admission finding above.

For this clarification, `bounded_tree.rs` was read from `m4-lsm-reviewed-source`; the unchanged `file.rs` was checked against its SHA-256 in `m4-storage-final-sources.json`. No runtime gate was rerun.

## Scoped re-review, fix round 1

Verdict: **Approved for the six original LSM/Muniment findings and this fix diff.** No new Important or Critical regression was found in the 19-file fix diff. This does not approve whole-store recovery, the host receiving layer, or the retained platform and qualification boundaries above.

1. **ADDRESSED: resident decoded work.** `bounded_read.rs:158-186` uses borrowed memtable entries, charges both visit and key/value decoded bytes before comparing or cloning, and applies this to shadowed and nonmatching entries. The new `bounded_read_tests.rs:190` covers zero and cumulative boundaries and repeated calls.
2. **ADDRESSED: delete admission.** `fjall_backend.rs:146-147` checks single deletes, and lines 177-181 preflight all puts and deletes before the mutation loop. `fjall_bounded.rs:165` checks the owner key and partition-plus-key recovery ceilings. The added test covers an oversized delete, batch preservation, and reopen.
3. **ADDRESSED: empty-prefix binary boundary.** `fjall_bounded.rs:75` represents the empty-prefix upper end as `None`; the Fjall forwarding method and `bounded_read.rs:145-150` carry that as unbounded rather than as an exact-key lookup. The fixture covers `0xff`-leading bytes in resident and flushed storage, including existence and non-UTF-8 inventory refusal.
4. **ADDRESSED: the reported index extent and out-of-extent handle defects.** `bounded_index_block.rs:40` checks header and declared payload against the metadata boundary before reading or requesting payload capacity. `bounded_segment.rs:59-68` checks each retained handle, including first and last, has room for a data header before the index. The fixture covers malformed header/payload extents and single/last out-of-extent pointers. This is not a proof that every possible in-extent corrupt pointer or every data block has been semantically validated at open.
5. **ADDRESSED: Miniz maximum-versus-actual decode work.** `bounded_inflate.rs:34-79` limits each output step to both exclusive ledgers' remaining decode allowance, the block ceiling, and 4096 bytes; it debits actual bytes produced before another step. Allocation and, for indexes, metadata capacities are precharged independently before reservation. The post-step debit cannot exceed the preauthorized remainder while those mutable ledgers are exclusively held; it is bounded work, not an unbounded post-hoc check. Data and index fixtures exercise cumulative exact/one-short work and multi-step output.
6. **ADDRESSED: late index visits.** `bounded_index.rs:42` precharges the validated declared count before the first entry traversal. The zero-budget and late-malformation fixtures verify that repeated failed validation consumes the shared visit budget.

The full-range behavior of existence is now explicitly tested and remains a documented availability limitation, not a false successful absence. The prior stale `bounded_prepare` comment was corrected.
