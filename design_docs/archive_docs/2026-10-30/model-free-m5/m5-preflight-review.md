# M5 empty-startup preflight review

Verdict: **not ready to run as written**. The intended scope is appropriate for a disposable startup preflight, but the launcher needs failure-safe scope ownership and narrower validation of its writable host mounts. This is not M5 acceptance review.

1. **High: interruption or a failed timeout-cleanup command can leave the owned scope running.** `m5-draft/run_native.py:45-64` only cleans up after the initial `proc.wait` times out. A `KeyboardInterrupt` or other exception during that wait bypasses cleanup, and either `systemctl ... kill` can itself time out and raise before the remaining escalation. `run_preflight.py:42-44` records failure but does not stop or reap the scope. The 240-second limit is therefore not a reliable bound on these paths. Use a `finally` path that terminates and reaps the specifically owned scope and launcher on all abnormal exits, with bounded fallbacks even if a `systemctl` call fails; record cleanup results and preserve existing logs. Establish ownership before issuing signals so a pre-existing scope with the same PID-derived name cannot be targeted.

2. **High: supplied GPU and display paths are writable host mounts without type or identity validation.** `m5-draft/run_preflight.py:34` and `run_native.py:71-80` accept any existing paths, then writable-bind the entire `gpu-dir` at `/dev/dri` and the supplied display path into runtime. An accidental personal directory as `--gpu-dir` exposes its contents for writes to all children, defeating the disposable-root guarantee. Require the intended render device only (or a verified staging directory containing only that device), and verify the display input is the intended Wayland Unix socket. Reject arbitrary files/directories before starting the scope. Preserve the previously tested device/socket identities when constructing the actual run.

3. **Medium: frame and feature claims exceed the checks.** `preflight_phase.py:26-32` verifies inference is compiled and that a file named `.png` exists; it does not check that the app binary has the authoring feature, or that the file decodes to a nonempty real frame. `run_preflight.py:20-26` records hashes but does not bind the app to build features/provenance. Check or document the exact authoring/inference build receipt against the frozen hash, and validate the captured image before asserting a real frame. The runtime counters are a single observation made before capture and app exit, so describe zero counts as the recorded snapshot, not an entire-process or model-load guarantee.

Reviewed the packaged `run_preflight -> preflight_phase -> namespace_phase` route and the used `run_native` helpers. All six original files matched the supplied SHA-256 manifest at review time. The checked-in custody fixture uses a marked fresh root and an ephemeral seeded test identity and grants custody only; the route probe requires an explicit broker refusal. The namespace code verifies network interfaces/routes and cgroup limits before children start, supplies fresh HOME/XDG and application roots inside the disposable mount, and saves child logs and failure receipts in ordinary failure paths. These are static observations, not a GUI runtime receipt. The separate Wayland/render descriptor probe does not establish successful rendering or the whole preflight. No build or runtime was executed in this review.
