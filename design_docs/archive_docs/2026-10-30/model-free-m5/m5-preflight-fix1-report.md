# Empty-startup preflight review fixes, round 1

Frozen files are `m5-draft/run_preflight.py`, `preflight_phase.py`, `run_native.py`, `namespace_phase.py`, `fixture_server.py`, `preflight.scn`, and `test_preflight_helpers.py`. A separate hash manifest was generated by the parent. No preflight process, app, custodian, or acceptance scenario has run.

The launcher assigns a random scope name, refuses a name that already exists, and records a cleanup sidecar. On abnormal exit it signals the systemd scope only after observing one of the launched process tree in the unit cgroup and identifying the unit invocation; each signal rechecks the same invocation. Failed or timed-out TERM is recorded and followed by bounded KILL; process-group termination and reap are attempted separately. Unverified scopes are not signalled. The monitored scope ownership behavior remains untested against a real systemd-run invocation.

The single render device must be an actual DRM render character device, and the Wayland path must be the current display's UNIX socket. Device/inode identities are recorded, checked immediately before launch, and checked again inside the namespace before any child starts. The child environment omits HOME and CODEX_HOME; XDG and app roots point into the disposable directory, and the namespace does not expose the host home. Viability with HOME omitted remains untested.

The fixed preflight scenario is restricted to an empty fixture and records startup only. Frozen binaries must match successful locked/offline build receipts and stable before/after source hashes; app and probe receipts must both declare authoring and inference, and use identical source inventories. The frame is decoded as a PNG, checked for reasonable nonzero dimensions and nontransparent pixels. Acquisition and client counters are labeled as a snapshot; model loads are not claimed.
