# Fjall worker lifecycle candidate

Eidetic `HEAD` and fetched `origin/main` both resolved to `c70ea2f419cd8328318cf0ec6e90705a0022a25f` before changes. The isolated Turnstone policy test passed, but combined gate failure does not record the actual holder or thread interleaving. The source exposes two independent races capable of keeping the lease alive after a store drop: registration occurs only when a spawned thread starts, and the old `BackgroundWorker::drop` decrements its counter before its `activity` field drops. Snapshot trackers held by activity can retain the owner lease.

Upstream release audit: remote tags list latest 2.x as `2.11.2` at `39113bf79dcc36890693d99c0006d8f8d484d51c`; its [background worker source](https://raw.githubusercontent.com/fjall-rs/fjall/2.11.2/src/background_worker.rs) still increments in `start` and decrements in `Drop` before field destruction, and its [keyspace](https://raw.githubusercontent.com/fjall-rs/fjall/2.11.2/src/keyspace.rs) waits on that counter. It is not a drop-in fix for this patched lease lifetime. Tag `3.1.13` is `cfcdce3ef8425c1877e45e9b3ab88ed667132d92`; its [database source](https://raw.githubusercontent.com/fjall-rs/fjall/3.1.13/src/db.rs) uses a different worker pool and `try_send` shutdown loop. [Upstream issue 260](https://github.com/fjall-rs/fjall/issues/260) concerns a bounded-channel shutdown deadlock in the v3 architecture; it does not establish a fix for the local v2 lease race. No upgrade or format compatibility claim follows from the audit.

The candidate registers the completion guard in `BackgroundWorker::new` before any of the four thread spawns. Guard is the last field, so activity and its lease carriers drop before the counter decrements, including an unstarted captured worker on spawn failure and a worker unwinding. Keyspace's completion load is Acquire to pair with the guard's Release decrement. External snapshot/iterator leases remain owned by their capabilities. No retry, unlock, new dependency or format change is introduced.
