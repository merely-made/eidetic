# Retained-clip owner worker: contract and migration

## Goal and boundary

Cold diagnostic B returned a Fjall WouldBlock error when reopening a Selection. Its actual lock holder is not recorded. The source independently opens the same retained-clips keyspace from the research worker and the shell, establishing a real overlap hazard. Capture-only C establishes readable A1/A2 layout, not a lock fix.

Use one dedicated worker for retained clips, shared by the shell and research Bridge. It owns at most one physical **bounded** Fjall store at a time, keyed by canonical retained-clips directory identity and exact `FjallOwnerLimits`. It processes each complete read, native retention, import, or export serially. On a root or owner-policy change it finishes the current operation, drops the owner completely, then opens the requested owner with exactly the new limits. A different process holding the store remains a real error. Missing-store reads do not create one. A failed open leaves no reusable owner and the next request may retry. Never fall back to `FjallStore::open`.

## Admission, bounds, and lifecycle

The service is independent of inference availability and uses the shell-owned private custody binding. The worker uses a finite FIFO, with configurable maximum accepted outstanding jobs and queued/in-flight payload bytes using the existing research storage preferences and settings rows. Admission checks counts and byte arithmetic before additional queue copies or file reads; producer export currently materializes its owned selected export/backing in `selected_retained_export`, so inspect or extend that existing extraction boundary to enforce its size before materialization rather than claiming the queue alone bounds it; overflow/full/closed/invalid settings refuse immediately and visibly. Each accepted job receives one completion or an explicit cancellation before execution; jobs are not overwritten. Running writes are not reported as cancelled or rolled back: they complete or fail, and stale UI completion is refused. Bound pending completions too, so a stalled UI cannot turn the result queue into unbounded memory. Charge the active operation and owned output as well as queued input, using checked arithmetic and the existing per-operation clip wire/body bounds. Bound the size of a single result before posting it. Disconnected receivers must release accounting and owned content. On shutdown, reject new work, explicitly resolve queued jobs without starting them, and let the current operation finish or fail and release its owner without an unbounded UI join. Storage I/O time itself is not guaranteed bounded by byte limits.

Each job snapshots root and exact owner policy plus its own operation read budget. `BudgetStore` remains per operation, including the research query's shared request ledger; sharing the physical owner never shares or resets budgets. All work using the store, including seal checks, is inside the worker's serialized operation. Preserve staging, file size/overwrite checks and existing owner write admission. No unbounded legacy writer or direct Fjall opener remains in production retained-clip paths.

Private jobs carry the shell-owned `PrivateBinding.bound` (or equivalent `ClipAccess::from_bound`) and captured epoch; normal `App::clip_sealer` currently returns a borrowed raw `RootIdentity`, which is not sufficient to carry custody validity across an asynchronous job. The binding is installed and retired by `shell_start_private_connect.rs`. Check before work and after work; a retired sealer refuses sealing/unsealing. The shell also revalidates current identity, generation, session, graph, admission, URL, target, destination, and relevant producer selection before applying a completion or opening/announcing its result. Preserve the existing `research_clip_document` before/after checks and the Bridge `clip_view_bounded` context recheck across the asynchronous boundary. Do not report stale success. A custody change during an already-running multi-put write may leave unreachable sealed objects, so do not promise transactional rollback; it must not publish an admission or successful UI result under the stale binding.

## Focused deterministic evidence

1. Red regression: with a real sealed fixture, barriers force a background query's read to hold the physical bounded owner while a shell-path reader/write is submitted. Existing independent opens reproduce WouldBlock. After repair, both accepted jobs complete in order via one physical owner, with no lost completion and no UI wait. Exercise real retention/import/export as well as reader/query, not a mock-only store.
2. Queue count and byte limits: hold the worker with a barrier, fill both independently, prove prompt refusal, FIFO distinct completions, checked overflow, result backpressure and release on receiver drop/shutdown. Check settings persistence, invalid values and changes without silent expansion.
3. Exact policy and root changes: finish prior operations, observe owner drop before new bounded open, test incompatible policies, canonical aliases, missing read and external lock refusal/recovery. No old policy may serve a new request. Compare distinct per-operation ledgers and show a tighter one still refuses.
4. Delay real completion across session, graph, selected target, source generation, root identity and custody epoch changes. Verify no stale reader, retained admission, playback or export success is delivered; queued writes reject before execution when stale. Verify normal current cases succeed.
5. Existing focused clip/research/shell tests plus locked/offline guarded gates, independent scoped review, matching build provenance, then bounded headed cold Selection/Note and full intact/fault runs. Preserve all failed receipts; the tests alone do not qualify native acceptance.

Implementation and tests have not yet started. This is the review packet for the approved ownership direction.

## Input and public API notes

Knot can check the actual editor source length and selected byte range before `export_knot_selection` copies backing. Redshank `export_selected_note` builds JSON from the annotation and source, including representation and fingerprint fields; a plain-text-only check is insufficient. Enforce a checked bound over every borrowed input field before the owner builds the export, or obtain a bounded owner export API if current fields cannot be accounted safely. Count full serialized/owned data, not merely user-visible text. A queue reservation must include a maximum permitted result or another bounded completion channel accounting scheme, and must be released for dropped receivers. Lowering a queue setting must not discard accepted work: reject new admissions until its outstanding usage is within the new bound.

The public `turnstone::retained_clip` module currently exposes direct synchronous retain/read/import/export wrappers. The authorized ownership cut migrates in-tree and identified sibling consumers to an explicit shared handle and removes any production bypass. A workspace-wide Rust search found only `address` used by sibling examples, which remains a pure address formatter. Separately launched inspector/test processes may use their own bounded owner only after the app owner has exited.

## Export claim and reserved completion amendment

Export has a distinct authorization boundary. Current `export_with_sealer` writes plaintext to a named temporary file before final rename, so a post-completion check cannot retract disclosure. The owner first constructs a size-bounded selected package in memory without creating any export file. The shell rechecks the request's session, graph, selected clip, destination, identity and current bound epoch before submitting a separately bounded commit job. The commit worker performs a fresh binding/target check and atomically claims a one-shot ticket before creating any plaintext file or persisting it.

One local publication authority must coordinate the ticket claim and **all** local binding-retirement and relevant scope/destination invalidations in a single atomic state, not a check followed by an unrelated atomic operation. For example, a generation-and-claim state can let retirement advance the generation so an unclaimed ticket's compare-and-swap fails, while recording an already-claimed write as allowed to finish. A concrete implementation must prove that `BoundSealer::retire` and every local invalidation affecting these tickets participates, including retirement discovered in the sealer itself; a shell-only cancellation is insufficient. No registry or publication lock may be held over file I/O or cause the UI to wait for an active write.

If invalidation wins before claim, no plaintext file is created. If claim wins, the authorized write may complete after retirement; report its actual outcome and do not claim cancellation or rollback. External custody changes that have not yet been locally observed cannot be made atomic with filesystem operations by this local authority. The guarantee is against locally observed retirement and current checks at claim, with that limitation stated honestly.

Every accepted job reserves enough bounded completion capacity before admission, including its worst-case output, and keeps that reservation until delivery or receiver drop. A stalled UI cannot block the sole owner from making progress while a research worker waits. The prepared package and commit job remain within finite count and byte accounting across the handoff. If capacity cannot be reserved, refuse before acceptance.

Required additional tests pause export before claim, retire binding or change the locally tracked target, and prove no temporary or final plaintext exists. A separate test pauses after claim, retires binding and verifies the actual write outcome without a false cancellation claim. Test no-clobber and overwrite semantics with real files. With a UI completion intentionally undrained, submit a research read and prove it completes or promptly refuses under the reserved limits without deadlock or unbounded output.
