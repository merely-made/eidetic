This was source review only: no builds, tests, app, fixture or scenario were run. The reported 1,262-pass library gate is separate; the ignored inspector and native M5 acceptance have not run.

1. **P1: The observer writes author identity and other raw record fields despite the explicit projection boundary.** `src/app/research_record_scope.rs:90-92` serializes the entire `RecordResult`. Its `snapshot.records` contains `PropertyRecordV1.author` and `method` (Eidetic `crates/eidetic-core/src/records/mod.rs:103-116`), plus unfiltered lifecycle and exclusion strings. The seam explicitly calls for an allowlisted observation without author or hidden private fields. The existing privacy test uses an empty record set and only checks that `owner_bindings` is absent (`src/app/research_record_owner_tests.rs:384-410`), so it cannot detect the disclosure. **Fix:** construct an explicit bounded projection containing only the approved query, result, exact evidence and identity fields; exclude author, unrelated private fields and owner bindings. Adjust the independent comparison to compare approved fields or use a separately protected digest rather than exporting the raw payload. Add a populated-record test with distinct private canaries and verify both current and historical observations.

2. **P1: The exited-process inspector does not independently establish complete, exact query inputs.** `src/trail_memory/m5_inspection.rs:33-45, 77-112` starts with the observed result, compares it with the sealed saved result, and only visits lifecycle entries already present in that result. At `:125-199` it similarly trusts the observed admissions list and checks each named source; it never proves that the list exhausts the eligible graph-owned sources or active assertion bindings, nor connects every `held.snapshot.sources` source ID/version/producer and every record evidence hash/selector to the independently read owner bytes. A missing input or wrong source version can therefore agree between the UI observation and saved result while these checks succeed. This is material to complete counts, no-match, and exact source evidence. The draft verifier remains unconditionally fail-closed, so this is a qualification gap, not a claim that a receipt already passed. **Fix:** independently enumerate the eligible graph-owned inputs within the explicitly recorded source scope, account for exclusions and duplicate projections, read their owner payloads, and compare exact source identity/version/producer and record evidence hash/scalar range to the saved snapshot. Verify all eligible active records and definitions, plus historical withdrawal semantics, with omission, wrong-version, wrong-selector, missing/corrupt byte and scope cases.

3. **P1: The purported read-only inspector can mutate the copied owner stores.** `src/trail_memory/m5_inspection.rs:52, 63-65, 252` calls `FjallStore::open`, which opens or creates a keyspace and partition (Eidetic `crates/muniment/src/fjall_backend.rs:71-87`), and `try_load_session_graph`, which acquires a writable/create lock (`src/session/try_load_session_graph.rs:8-13`, `src/session_persistence.rs:15-22`) and may persist graph migrations (`src/session/try_load_session_graph_locked.rs:25-31, 57-66`). This violates the requested read-only independent inspection and can alter evidence before verification. **Fix:** use owner-backed read-only, no-create store and graph loading APIs that refuse migration/recovery requirements, or provide an equivalently verified immutable input and a proven read-only reader. Test missing/corrupt/migration-needed inputs and compare a complete input tree hash before and after inspection, including failure paths.

4. **P2: Structured evidence does not record the effective source-selection mode.** `src/app/research_record_scope.rs:75-92` exports graph and result identities but omits `scope.selected`, even though `None` means all admitted sources and `Some(empty)` means explicitly none (`:172`). A snapshot with no sources cannot itself establish which mode produced it; the separate search summary is only available on another view and does not bind the structured result to that selection. **Fix:** include an explicit current-result selection projection distinguishing all, none and exact chosen IDs, scope-checked with the result, and test all three modes and stale selection. This should feed the independent inventory check above.

The note-member helper identifies one existing painted member, sends ordinary pointer events and checks the resulting selection (`src/shell/drive/shell_scenario_click_note_member.rs:7-48`); its headed route remains untested. The inference counters are placed at client route and intent attempts and explicitly leave resident model loads unknown (`src/inference_activity.rs:13-22`, `src/inference_service/intent.rs:11-17`, `src/inference_service/worker.rs:69-70`). Their labels should be interpreted as client attempts, not resident load evidence. The structured and comparison hooks do not invoke the evaluator or store.
