# Fault-copy custody socket handling

The isolated custodian fixture leaves one `run-<uuid>/custody.sock` for each real process. The fault runner previously rejected all sockets while inventorying the whole intact collection and when copying `sandbox/custody`, so a successful intact run would fail before fault injection. The outer `app.sock` is removed by the normal successful collector; it remains forbidden in this fix.

`collection_tree` still inventories every directory and regular file, rejects symlinks, hard links and unrecognized nonregular entries, and records device/inode/mode for only the exact `sandbox/custody/custodian/run-<canonical uuid>/custody.sock` pattern. The same complete inventory is compared before and after the fault phase, so those original sockets remain untouched. `copy_custody` rejects extra root entries, validates each runtime directory contains only its expected socket, and copies only the synthetic fixture's persistent `data`, `vault`, `initialized`, `client.json`, marker and lock. It verifies separate copies and leaves runtime sockets behind. The fixture itself creates a fresh per-process runtime on reopen. `READY_FOR_FAULT_COLLECTION` remains false.
