# Retained-clip owner overlap: proposed cut

## Evidence and scope

Copied cold run B attempted to open a retained Selection and returned `Retained clip storage open: backend: fjall open: operation would block`. The receipt does not identify the lock holder or prove exact overlap timing. This is separate from the narrow pane layout. Source inspection confirms an in-process independent-open hazard: `src/retained_clip.rs` opens bounded Fjall independently in `open_with_limits` (retain, import, export) and `read_sealed_bounded` (research search/comparison and readers). The shell converts a read error to `ContentFailed` in `shell_effect_spawn_content.rs`; it does not automatically retry. External processes can still legitimately hold the store and must receive a truthful error.

## Proposed smallest cut

One process-local, bounded registry maps canonical retained-clips directory identity to a slot and owns exactly one `Arc` of the bounded `FjallStore` for a compatible policy. All production retained-clip reads, native writes, imports and exports go through that one entry point. Check directory existence/create policy before canonicalization, then canonicalize and verify directory identity so aliases do not produce two independent owners. A filesystem replacement or inability to verify identity fails closed; do not broaden admission or create on read. Registry capacity must be finite and idle slots reclaimed.

A slot carries the exact `FjallOwnerLimits` (recovery and per-read owner ceilings). A matching active lease can share the owner, while an incompatible policy refuses immediately while leased. Once the last lease ends, close the old owner and allow reopening under the new exact limits. Operation limits are not owner identity: preserve the existing distinct `BudgetStore` and request-wide `SharedReadBudget` for each operation. Preserve all existing sealer, destination, session, graph, admission and before/after custody-generation checks. Also preserve the old owner-exclusive operation boundary: retained/import writes span multiple store calls, so coordinate writes exclusively against reads/exports with nonblocking admission, unless a separately proven atomic publication contract makes this unnecessary. Fleece deposits selected parts before the final retained record, but that ordering alone does not establish atomic visibility of all existing shared objects and seal state.

Slot state must reserve Opening and Closing until open or actual final owner destruction completes. A bare `Weak` is insufficient: its upgrade may fail before the destructor releases the file lock. Serialize state transitions with short, nonblocking bookkeeping; never hold a UI-contended lock across open, close, read or write. On contention or an opening/closing slot, return a specific transient refusal rather than block the UI or attempt a duplicate open. Opening failure and unwind must release the reservation. This avoids introducing an unbounded UI lock wait; the existing bounded synchronous disk operations remain synchronous. A transient first-open collision is not automatically retried by current content handling, so correctness must either explicitly retain a retryable UI state or route retry through an appropriately bounded worker before claiming the collision is resolved. Do not mask it as a completed reader.

The existing research worker has one running request and one replaceable pending request/response across search, comparison and records. Adding reader or write jobs there would let unrelated jobs replace one another. A dedicated async single-owner actor could serialize all operations and deliver retries off the UI, but needs separate bounded queues, cancellation, multiple readers and write/custody revalidation; it is a materially larger cut. Prefer the registry if the first-open transient is handled without an unbounded wait or lost action. If that cannot be done, use a separately bounded owner actor rather than pretend the current worker provides reliable delivery.

## Required focused evidence

- With a real sealed clip store and barriers, keep a bounded owner leased by one thread while a second research read and native/import/export path execute against the same owner. Assert correct data and no independent Fjall open or WouldBlock; prove aliases resolve to the same store.
- Force simultaneous first-open, failed open and last-lease close using deterministic barriers; assert no second physical open, reservation cleanup, and explicit bounded retry behavior.
- Verify exact owner-policy mismatch refuses while leased and the requested changed policy is installed only after release/reopen. Different operation budgets must remain independent and a stricter operation ledger must still refuse over-budget reads.
- Exercise the actual content completion or retry path and stale session/admission/custody generation rejection across delayed completion. No stale data or writes may escape.
- Run focused locked/offline tests through the existing shared guard, review the exact source packet, then repeat bounded headed Selection/Note reopen with real overlapping research and independent store inspection. A unit overlap alone is not native qualification.

This is a source-grounded proposal, not an implementation or acceptance claim.
