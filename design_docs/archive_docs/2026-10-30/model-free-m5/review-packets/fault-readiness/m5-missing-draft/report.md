The exact fault is feasible with current owner interfaces. The graph capture facet names a `sealed-v1:` annotation manifest. `trail_memory::sealed_capture::content` validates that annotation and reads its authoritative raw manifest as a sealed `OpaqueBlob` with `eidetic::NoFetcher`; it refuses when that raw payload is missing. The raw manifest's local source is `blob:<content hash>`. `muniment::Backend::delete` removes a single owner key and `FjallStore::sync_all` synchronizes it. `eidetic::delete_manifest` only removes the manifest and deliberately retains bytes, so it does not perform this fault. The helper deletes the raw ciphertext, leaving the raw manifest, sealed capture receipt, annotation, graph reference, primary profile and A2 intact. The owner's content hash is of clear raw bytes; the receipt also records a distinct hash of the deleted ciphertext.

The ignored-test helper draft `fault_helper.rs` is a proposed child module of the current `m5_inspection` module, so it can call its strict graph reader and the existing private sealed-capture owner. Hook it from one ignored `research_owner_tests` test only after source integration and review. It requires a fixed `/m5/fault-copy` mount, UUID marker and fixture custody endpoint, verifies the two graph facet references and exact owner reads, requires the A1 and A2 raw identities differ, checks all capture references in the graph against `all_admissions`, rejects any other capture sharing A1 raw bytes, verifies the raw sealed local manifest and hashes its ciphertext, deletes one key, syncs, reopens, and checks absence, manifest preservation, A1 owner refusal and unchanged A2. It writes a create-new receipt. This is deliberately narrower than changing production APIs or storage format. The writable Fjall open can perform recovery and other internal writes on the **fault copy**, so compare semantic evidence and graph bytes at the boundaries; do not claim that a Fjall file-tree diff consists of only one file/key. It is not a read-only inspector.

The input is `turnstone.m5-missing-input/v1`: `run_id`, `a1_admission`, `a1_target`, `a1_content`, `a2_admission`, `a2_target`, `a2_content`, `all_admissions`. Construct it only after the seed and intact fresh reopen have both completed, using the same run's ledger-bound intact A1/A2 reader observations and independent owner inspection. The helper independently checks the values against the copied graph and actual owner. Refuse absent, duplicate or ambiguous matches and any identity, version, selector or hash mismatch.
